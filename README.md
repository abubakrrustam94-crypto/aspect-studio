# Aspect Studio

Смена формата фото без обрезки: размытый фон, пресеты для соцсетей и маркетплейсов, улучшение качества, пакетная обработка и ZIP.
Всё работает в браузере, фото никуда не загружаются. Без фреймворков и сборки.

## Структура

```
index.html          разметка
css/style.css       стили
js/core.js          константы, состояние, тема, загрузка изображений
js/render.js        раскладка, рендер, улучшение качества (Web Worker)
js/analyze.js       анализ фото: резкость, шум, главный объект
js/preview.js       предпросмотр и слайдер
js/ui.js            настройки, миниатюры
js/export.js        экспорт, ZIP
js/features.js      горячие клавиши, просмотр 100%, обрезка, наборы, вкладки
js/onboarding.js    мини-обучение при первом запуске (кнопка «?» открывает снова)
js/main.js          старт
fonts/              шрифт Roboto Flex (локально)
sw.js, manifest.json, icon*.png   PWA и офлайн
tests/run.js        автотесты (Playwright)
```

Скрипты подключаются в index.html по порядку, менять порядок нельзя.

## Запуск локально (Termux)

```bash
pkg install python
cd aspect-studio
python -m http.server 8080
# открыть http://localhost:8080
```

## Деплой на GitHub Pages

1. Создай репозиторий на github.com (например `aspect-studio`), публичный.
2. В папке проекта:
   ```bash
   git init
   git add .
   git commit -m "Aspect Studio"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_НИК/aspect-studio.git
   git push -u origin main
   ```
   В Termux перед этим: `pkg install git`. При push GitHub попросит логин и токен
   (Settings → Developer settings → Personal access tokens, право `repo`) вместо пароля.
3. В репозитории: Settings → Pages → Build and deployment → Source: «Deploy from a branch»,
   Branch: `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты сайт будет по адресу `https://ТВОЙ_НИК.github.io/aspect-studio/`.

Все пути в проекте относительные, поэтому сайт работает и в подпапке репозитория.

## Имя файла

В настройках экспорта можно задать шаблон: `{name}` исходное имя, `{n}` номер по порядку (01, 02…), `{w}` и `{h}` размер, `{date}` дата, `{k}` номер внутри группы (одинаковое соотношение сторон или пресет), `{ratio}` соотношение (`16x9`), `{preset}` название пресета.
Например `{n}_{name}` даст `01_photo.jpg`. Порядок фото меняется кнопками ◀ ▶, сортировкой или перетаскиванием.
Есть нумерация с любого числа, транслитерация (кириллица и таджикские буквы → латиница) и замена пробелов на `_`.

## ZIP на диске

В «Экспорте» есть переключатель «Собирать ZIP на диске». Архив пишется потоком во временный файл
приватной файловой системы браузера (OPFS), в памяти остаётся только текущее фото. Нужен https или localhost:
при открытии файла напрямую (file://) или в старых браузерах сайт сам соберёт ZIP в памяти.
Временные файлы удаляются через 10 минут и при следующем запуске.

## Данные и приватность

- Фото обрабатываются только на устройстве и никуда не отправляются.
- «Мои наборы» (вкладка «Ещё») можно сохранить в файл `aspect-studio-presets.json` и загрузить на другом устройстве; при импорте наборы с одинаковым именем обновляются, неизвестные поля отбрасываются.
- «Сбросить все настройки» (вкладка «Ещё → О программе») стирает настройки, наборы, акцент и тему этого браузера; нужно нажать дважды.
- Версия приложения — константа `APP_VERSION` в `js/core.js`.

## Приватность и экспорт (v2.9)

- **Метаданные.** «Удалить всё» (по умолчанию): в файле нет EXIF, геолокации и серийных номеров. «Дата и камера»: переносятся только производитель, модель и дата съёмки. Геолокация не копируется никогда. Имя автора и копирайт можно вписать отдельно, они записываются и в режиме «Удалить всё».
- **Цвет.** Display P3 сохраняется, если браузер его поддерживает и в исходнике есть профиль P3. Переключатель «sRGB» переводит цвета в sRGB для сайтов и маркетплейсов.
- **Папка.** В Chrome/Edge на компьютере и Android файлы можно сохранять прямо в выбранную папку (File System Access API); существующие файлы не перезаписываются (`_2`, `_3`…). Выбранная папка запоминается, доступ браузер при необходимости запросит снова.

## Водяной знак (v2.10)

Знак (текст или свой логотип) можно поставить в один из девяти углов или раскинуть **мозаикой** по всему кадру: шаг, наклон от −90° до 90°, размер и прозрачность настраиваются, чётные ряды сдвигаются на полшага. Мозаика одинаково рисуется в превью и в экспорте. Для защиты от зависаний слишком мелкий шаг ограничен.
**Шаблоны знака** хранят текст, логотип (уменьшенный до 480 px), расположение, размер, прозрачность, шаг и наклон; применяются одним нажатием и переживают перезагрузку. Общие «Мои наборы» настроек, их экспорт и импорт работают как раньше.

## Большие фото (v2.11)

Фото больше `MAX_AREA × 2.5` пикселей (примерно 20–40 МП в зависимости от памяти устройства) открываются сразу в уменьшенном виде: полный кадр не попадает в память. Приложение пишет об этом, а в строке информации появляется пометка. Размеры исходника берутся из заголовка файла с учётом EXIF-поворота. Если браузер не смог декодировать и такой размер, пробуется ещё меньший (до 28% от лимита), и только потом файл отклоняется. Итог всегда ограничен `MAX_AREA`, поэтому для обычных задач потери нет; заметна она только при очень сильной обрезке.

## Доступность и «Что нового»

`tests/a11y.js` гоняет axe-core по всем вкладкам, обеим темам и окнам; серьёзные нарушения (контраст, подписи) валят тест. Список изменений лежит в `CHANGELOG.md` и в `js/changelog.js`; после обновления приложение один раз показывает окно «Что нового» (при первом запуске — нет). Тест `tests/whatsnew.js` следит, чтобы версия приложения, `package.json` и первая запись списка совпадали. При выпуске новой версии: поднять `APP_VERSION`, `package.json`, `VERSION` в `sw.js`, добавить запись в оба файла списка.

## Определение лиц (v2.12)

Лёгкая модель BlazeFace (MediaPipe) ищет лица при анализе фото. В режиме «Заполнить» с включённым автоцентрированием кадр смотрит на лица и по возможности оставляет в кадре все, с небольшим запасом; лицо чуть выше центра. Если на кадре лиц не нашлось, используется поиск главного объекта по краям, как раньше.
- **Лениво и офлайн.** Рантайм и веса (около 1,5 МБ) лежат в `vendor/blazeface/` и скачиваются при первом анализе; Service Worker кэширует их, дальше всё работает без сети. Если при первом запуске сети нет, анализ завершается без лиц, а в подсказке сказано, что нужен интернет; следующий анализ пробует снова.
- **Быстро и без подвисаний.** Вычисления идут в воркере (`js/faces-worker.js`), на WASM (на старых браузерах — на CPU). Обычный кадр занимает десятки миллисекунд; если лиц нет, дополнительно проверяются 4 перекрывающихся фрагмента (мелкие лица на больших кадрах).
- **Приватность.** Фото не покидают устройство, поиск лиц — переключатель «Искать лица» в «Качество → Анализ фото».
- Порог уверенности 0,75: на тестовых кадрах (портрет, два лица, мелкое лицо, кофе, ракета) нет ни пропусков, ни ложных срабатываний. Тестовые фото: NASA и scikit-image (общественное достояние / CC0).
- Не работает при открытии `index.html` как файла (`file://`): браузеры блокируют воркеры. На GitHub Pages и локальном сервере всё в порядке.

## Удаление фона (v2.13)

Вкладка «Фон» → «Удалить фон». Объект вырезается моделью U²-Net-P (подходит для товаров, людей, животных), а фон заменяется на белый, выбранный цвет или прозрачный (PNG и WebP; в JPG прозрачность невозможна, там будет белый). Новый фон заменяет и поля вокруг фото, и в режиме «Заполнить».
- **Как считается.** Модель (2,2 МБ) в воркере на WASM даёт грубую маску 320×320 за 1–3 с. Затем край подтягивается к границам объекта на самом фото направляющим фильтром (рабочее разрешение маски до 1024 px), а ползунок «Край» задаёт резкость перехода. Маска кэшируется на фото и пересчитывается только после поворота, отражения или обрезки.
- **Лениво и офлайн.** Рантайм общий с поиском лиц (`vendor/tfjs/`), модель лежит в `vendor/cutout/`; скачиваются при первом включении, Service Worker кэширует, дальше работает без сети. Нет сети при первом включении: фото сохраняется как обычно, пользователю сказано, что нужен интернет, повтор не раньше чем через 15 с.
- **Если объекта нет** (маска закрывает меньше 2% кадра), фон остаётся как был, с сообщением.
- **Ограничения.** Модель небольшая: тонкие детали (волосы на светлом фоне, сетки, прозрачные предметы) вырезаются приблизительно, ручной кисти для доработки маски нет. Как и лица, не работает при открытии `index.html` как файла (`file://`).

## Компоненты (v2.14)

Тяжёлые модули лежат в `vendor/` и не скачиваются сами. Вкладка «Компоненты» качает их по кнопке в Cache Storage (`aspect-studio-components`), Service Worker отдаёт `/vendor/` только из этого кэша. Без компонента функция показывает предупреждение с кнопкой перехода во вкладку. Реестр: `COMPONENTS` в `js/components.js` (размеры файлов проверяет `tests/components.js`). Без Cache API всё грузится по требованию.

## Удобство (v2.16)

`js/session.js`: история настроек (снимки общих и пофото настроек, до 60 шагов), «Сбросить фото», необязательное сохранение фото в IndexedDB (`aspect-studio-session`, включается переключателем, по умолчанию выкл., стирается кнопкой и «Сбросить все настройки») и `share_target` в манифесте: `sw.js` принимает POST на `./share-target`, кладёт файлы в кэш `aspect-share`, страница забирает их по `?shared=N`.

## Скорость (v2.17)

Тяжёлые пиксельные операции (Lanczos, шумоподавление, резкость) и раньше шли в Web Worker. Теперь `pooledExport` в `js/export.js` держит в работе до 3 фото сразу, у каждого свой воркер (`exPool`), а результаты принимает строго по порядку. Число потоков: `exportConcurrency` (память устройства, ядра, размер кадров). Измерения: на 2 ядрах 12 фото с улучшением 2× быстрее на 17% при 2 потоках и на 25% при 3. Скрипты не подгружаются лениво: на ускоренной в 6 раз эмуляции слабого телефона все файлы приложения разбираются быстрее 0,6 с, выигрыш был бы незаметен.

## Качество результата (v2.18)

Вес файла в превью (`weightPill` в `js/preview.js`): оценка по холсту предпросмотра с пересчётом на площадь, по нажатию точный расчёт через `exportBlob`. Ручная правка маски: `js/maskedit.js` пишет прямо в `item.mask.data` (рабочее разрешение до 1024 px), исходная маска нейросети хранится в `mask.orig`; при смене поворота или обрезки маска пересчитывается и правки теряются. Пресеты сверены 21.10.2026: WB, Ozon, Яндекс Маркет 3:4 (от 900×1200), Авито 4:3 (от 1600×1200), Ozon Fresh 1:1 (размер 1000×1000 принят по умолчанию, точной цифры в источниках нет).

## Метаданные (v2.19)

`js/metadata.js`: полный разбор JPEG (EXIF, JFIF, XMP, IPTC), таблица «Было → Будет» (`metaRows`), профили, проверка готового файла (`inspectBlob` для JPG, PNG, WebP). Запись: `metaOpts` и `buildSafeExif` в `js/export.js`. Принцип прежний: геолокация, серийные номера, программа, объектив, миниатюра, XMP и IPTC не переносятся никогда. Новые настройки: `metaCam`, `metaDate` (keep/today/none), `metaCopy` (шаблон), `metaDpi` (JFIF + EXIF для JPG, pHYs для PNG); режим `meta` получил значение `custom`.

## Точное удаление фона (v2.20)

Общий ONNX-движок: `js/ort.js` + `js/ort-worker.js` (onnxruntime-web 1.30, WASM в один поток, сессия одна, воркер закрывается через 45 с простоя). Файлы движка: `vendor/ort/`. Модель IS-Net (int8, из пакета `@imgly/background-removal-data`, исходная модель DIS, Apache-2.0) лежит в `vendor/models/isnet-int8.onnx.p1` и `.p2` (две половины, склеиваются в воркере); версия fp16 (88 МБ) почти не отличается по результату и не включена. Выбор качества: настройка `cutQuality` (fast/precise), компонент определяет `cutComp()`. Сайт личный, поэтому лицензии на некоммерческое использование допустимы.

## Форматы фото на входе

| Как открывается | Форматы |
|---|---|
| Самим браузером | JPEG, PNG, GIF (первый кадр), BMP, ICO, WebP, AVIF |
| Собственным кодом (без библиотек) | **RAW** (CR2, CR3, NEF, NRW, ARW, RAF, ORF, RW2, DNG, PEF, RWL), **PSD / PSB**, **HDR**, **SVG**, **EPS** (встроенное превью), **XCF** |
| Подгружаемыми декодерами (`vendor/`, один раз) | **HEIC / HEIF**, **TIFF / TIF**, **EXR**, **JXL**, **AI** |

Что важно знать:
- **RAW:** берётся самое большое JPEG-превью внутри файла. Это снимок «как с камеры», а не проявка RAW-данных: баланс белого, экспозиция и шумоподавление не пересчитываются. Размер превью зависит от камеры (у многих — полный кадр, у некоторых 1–2 Мп); приложение показывает, какое превью открыто. Проверялось на синтетических файлах в формате контейнеров, реальные снимки со всех камер проверить невозможно.
- **PSD / PSB:** читается готовое «склеенное» изображение (оно есть, если при сохранении было включено «Максимальная совместимость»). Слои не разбираются. 8 и 16 бит, RGB, градации серого, CMYK (приблизительно), индексированные; Lab и 32 бита — нет.
- **HDR / EXR:** тонмаппинг упрощённый (линейный свет → sRGB; если есть значения ярче 1, кадр масштабируется по 99,5-му процентилю).
- **SVG:** отрисовывается в растр 2400 px по длинной стороне (максимум 4096), прозрачность сохраняется. Внешние картинки и шрифты внутри SVG браузер не подгружает.
- **AI:** открываются только PDF-совместимые файлы (первый монтажный стол); старые AI на основе PostScript — нет.
- **EPS:** PostScript браузер выполнить не может, поэтому берётся встроенное превью (обычно низкого разрешения); если превью нет — сообщение.
- **XCF:** упрощённо: слои в обычном режиме с прозрачностью, 8 бит на канал. Режимы наложения, маски слоёв, группы и 16/32 бита не поддерживаются. Проверено на файлах, собранных по спецификации формата, не на файлах из реального GIMP.
- **TIFF:** многостраничный — берётся самая большая страница; BigTIFF и раздельные плоскости (Planar) не поддерживаются.
- **HEIC:** в Chrome на ПК и Android без поддержки HEIC файл конвертируется встроенным декодером; фото с iPhone в Safari открываются самим браузером. Конвертация идёт в главном потоке, на 12+ Мп страница на секунду-две замирает.
- Очень большие кадры (более 24 Мп после конвертации) временно хранятся как JPEG (качество 97) вместо PNG, чтобы не ждать кодирования.
- Тест: `node tests/formats.js` (файлы-образцы в `tests/fixtures`, генератор — `tests/make_fixtures.py`).


## Сжатие и форматы вывода (v2.21)

`js/enc.js` + `js/enc-worker.js`: кодирование в отдельных потоках (до двух, закрываются через 45 с простоя). Компоненты `encjpeg` (MozJPEG), `encpng` (oxipng + собственная палитра: срез до 5/5/5/4 бит, медианное сечение, Флойд–Стейнберг), `encavif`, `encjxl` лежат в `vendor/enc/`. Настройки: `jpgEngine` (native/moz), `pngOpt` (off/lossless/lossy), `pngColors`, `encEffort` (fast/normal/best). `encodeBlob(canvas, fmt, q)` — единая точка входа; без компонента используется `canvas.toBlob`. P3 в JPG/PNG сохраняется профилем, взятым у самого браузера, в AVIF/JXL — перевод в sRGB. Тест: `tests/encode.js`.

## RAW через LibRaw (v2.22)

Компонент `raw` (`vendor/raw/worker.js` + `libraw.wasm`). `rawDevelop()` в `js/formats.js` создаёт модульный воркер на один снимок, проявляет (AHD, баланс белого камеры или авто, sRGB, 8 бит, ориентация из файла; на устройствах с памятью ≤3 ГБ — половинное разрешение), закрывает воркер и отдаёт обычный файл. Настройки `rawMode` (full/preview) и `rawWb` (camera/auto) действуют на файлы, добавленные после изменения. Если проявить не удалось — открывается встроенное превью. Тест: `tests/raw.js` на синтетических DNG (`tests/make_raw.py`).

## Нейро-увеличение (v2.23)

`js/sr.js`: Real-ESRGAN ×4 на общем движке ONNX (`js/ort.js`). Три модели-компонента: `srfast` (animevideo v3), `srgen` (general v3), `srmax` (x4plus, две части). Настройка `srModel` (off/fast/general/max, переопределяется для каждого фото). Считается плитками (128+12 или 80+10 пикселей перекрытия) только при полном рендере (`!cap`: сохранение и «Проверить на 100%»), результат ×4 затем уменьшается до нужного размера обычным конвейером (Lanczos, резкость). Один готовый результат кэшируется (`srSlot`). Пропускается, если итоговый кадр меньше 1,2× исходного или фото больше предела модели. Модели собраны без torch: `tools/pth_reader.py` читает `.pth`, `tools/build_esrgan_onnx.py` строит граф ONNX (`python3 tools/build_esrgan_onnx.py weights.pth compact|rrdb out.onnx [half]`). Тест: `tests/sr.js`.

## Нейро-шумоподавление (v2.25)

`js/dn.js`: FFDNet (`dnffd`, уровень шума 8/18/32 из 255) и SCUNet (`dnscu`, две части, слепое шумоподавление; «уровень» — доля очищенного кадра 50/75/100 %). Модели собраны под плитку ровно 256×256 (`tools/build_denoise_onnx.py`, веса fp16). Область фото режется на ядра по 224 px с перекрытием 16 px, плитки у края сдвигаются внутрь кадра, а кадр меньше плитки дополняется дублированием края. Настройки `dnModel` (off/ffd/scu, переопределяется по фото) и `dnLevel` (1–3). Считается только при сохранении и в «100%»; очищенная область кэшируется (`dnSlot`), и нейро-увеличение берёт её как исходник (ключ кэша увеличения включает `dnModel`+`dnLevel`). Тест: `tests/denoise.js`.

## Хранение компонентов и фоновая загрузка (v2.29)

`js/components.js`: файлы компонентов лежат в OPFS (`aspect-components/`, имя файла = `encodeURIComponent(путь)`); проверка — размер файла = размеру в реестре, неполный файл считается «повреждённым». `compStoreMode()` возвращает `'opfs'` или `'cache'` (в `localStorage` ключ `aspect-studio-compstore=cache` принудительно включает старый режим; им пользуются тесты, проверяющие Cache Storage). `compFetchFileOpfs()` пишет поток прямо в `createWritable()`, при ошибке или отмене файл удаляется. Старые компоненты из Cache Storage читаются как раньше (`compOld`), `compMigrate()` переносит их в OPFS. `sw.js` для `/vendor/*` сначала смотрит в OPFS, затем в кэш, затем в сеть.

Фон: `compBgStart()` запускает `registration.backgroundFetch.fetch()` (запросы вида `…?sz=<байты>`), `compBgRun()` следит за прогрессом; если за `COMP_BG_STALL_MS` (12 с) не пришло ни байта, фон отменяется и качает страница. Событие `backgroundfetchsuccess` в `sw.js` пишет записи в OPFS (проверяет размер из `?sz=`) и сообщает странице через `BroadcastChannel('aspect-studio-comp')`; `compBgResume()` при старте подхватывает идущие загрузки. Тест `tests/opfs.js` проверяет OPFS, перенос, отмену и откат; сам Background Fetch в headless Chromium ничего не качает, поэтому ветку `backgroundfetchsuccess` нужно проверять вручную на телефоне.

## Цветовые профили ICC (v2.27)

`js/icc.js` + `vendor/icc/` (компонент `icc`: LittleCMS `lcms.js` + `lcms.wasm` из lcms-wasm 1.0.5, профили из Compact-ICC-Profiles, CC0). Значения `colorSpace`: srgb, p3 (как раньше, профиль берётся у браузера), adobe, rec2020, prophoto, source. Для новых режимов холст рисуется в Display P3, если исходник широкий (`ICC_WIDE`, `wantP3`). Перед кодированием `iccApply()` переводит пиксели полосами по ~1 МП (RGBA 8 бит, относительная колориметрия с компенсацией чёрной точки; альфа берётся из исходных пикселей: lcms её портит) в новый sRGB-холст, который хранит числа профиля вывода, чтобы браузер не вшил свой профиль. `iccEmbed()` дописывает APP2-сегменты в JPG или чанк iCCP в PNG (sRGB/gAMA/cHRM удаляются). Профиль исходника читает `iccFromFile()` (JPEG APP2 с несколькими частями, PNG iCCP через `DecompressionStream`); не RGB-профили отбрасываются. WebP/AVIF/JXL: предупреждение и обычный цвет. Тест: `tests/icc.js`.

## Убрать лишнее (v2.26)

`js/erase.js`: экран `#erEd` (кисть по маске в разрешении ≤1600 px) и MI-GAN (`erase`, `vendor/models/migan.onnx`, вход 512×512: канал 0 = 0,5 − дыра, каналы 1–3 = RGB в [−1; 1] без дыры; выход RGB в [−1; 1]; модель собрана из TorchScript Sanster/models, fp16-хранение). Метки склеиваются в области (сетка 16 px, связность ±2 клетки); для каждой вырезается квадрат ≈1,8× области (не меньше 256 px и не больше короткой стороны), дыра расширяется на 4 px (на 512), результат масштабируется обратно и кладётся поверх только внутри дыры. Итог запекается в PNG и подменяет `item.file` (сбрасываются поворот/обрезка/маска/кэши; шаги отмены настроек очищаются); прежнее состояние хранится в `item.erased` (до трёх), исходный файл для EXIF — в `item.exifSrc`. Тест: `tests/erase.js`.

## Многопоточные нейросети (v2.31)

Service worker добавляет к ответам сайта заголовки `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: credentialless`. Страница становится `crossOriginIsolated`, а ONNX Runtime получает `SharedArrayBuffer` и считает в нескольких потоках (замеры на 2 ядрах: MI-GAN ×2,3, SCUNet ×1,7, FFDNet без выигрыша). Число потоков: «Ещё → Скорость нейросетей» (Авто, 1, 2, 4; не больше числа ядер). Без изоляции (первый запуск до установки service worker) движок работает в один поток. WebGPU не используется: его нельзя проверить без видеокарты, а нужный wasm ещё на ~25 МБ. Тест: `node tests/threads.js`.
